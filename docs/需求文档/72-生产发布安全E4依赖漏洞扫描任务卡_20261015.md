## 0. 目标与范围

**目标**：在 Gitea Actions CI 中落地软件成分分析（SCA），对标阿里云效依赖包漏洞检测的分级门禁（BLOCKER/CRITICAL/MAJOR = NVD CVSS），实现「引入即扫、发布前强制扫、周巡检、0day 可溯源」。覆盖 69 号文档 E4 九节：①工具链 ②触发策略 ③分级门禁 ④多源数据 ⑤修复 SOP ⑥SBOM ⑦周巡通知 ⑧落地注意 ⑨可选增强。

**范围**：
- 后端：13 个 Maven 模块（根 `pom.xml` reactor：`xfwl-common/xfwl-base/xfwl-oms/xfwl-work/xfwl-user/xfwl-file-server/xfwl-service-api/xfwl-web/xfwl-dispatch/xfwl-aggregation/xfwl-netty/xfwl-gateway/xfwl-auth`）
- 前端：`xfwl-admin-ui-vue3`（管理端）、`xfwl-mobile`（司机/快递员/客户三端 H5）
- 镜像：随 E5 一并 trivy 扫描（本卡预留 job，不阻塞 E4 验收）

**不做（防范围蔓延）**：
- 不引入商业 SCA 平台；OWASP Dependency-Check 免费开源即达标
- 不要求首发前清零存量 Medium/Low（按 ⑧，suppress + 台账消化）
- 不重写历史；只加 CI 卡点 + 根 pom 插件

## T-SEC-E4 依赖漏洞扫描实施 ★P1（可独立并行）

### 涉及文件（均已核验存在）

| 文件 | 改动 |
|---|---|
| `pom.xml`（根 reactor） | 新增 `dependency-check-maven` / `cyclonedx-maven-plugin` / `maven-enforcer-plugin` 三个插件声明 |
| `ci/dependency-check-suppressions.xml`（新建） | suppression 清单（接受风险项 + 理由 + 复查日期） |
| `ci/dependency-check.properties`（新建） | NVD 数据缓存/超时/有效时长配置 |
| `.gitea/workflows/sca.yml`（新建） | SCA 主工作流（push 触发 + 周巡 cron + 手动 dispatch） |
| `.gitea/workflows/build-check-fe.yml`（改） | 前端 job 加 `pnpm audit` 步 |
| `docs/需求文档/`（可选） | 漏洞台账 markdown（分级/SLA/责任人），或复用 C4 看板 |

### 实施步骤

**① 根 pom 引入扫描插件（工具链）**
在根 `pom.xml` 的 `<build><plugins>` 加入（用 `pluginManagement` 统一版本，各模块按需激活）：

```xml
<!-- 依赖漏洞扫描：OWASP Dependency-Check（CVSS v3.1，数据源 NVD） -->
<plugin>
  <groupId>org.owasp</groupId>
  <artifactId>dependency-check-maven</artifactId>
  <version>12.1.0</version>
  <configuration>
    <!-- 门禁线：CVSS≥7.0（High/Critical）即失败；对标云效 CRITICAL/BLOCKER 阻断 -->
    <failBuildOnCVSS>7</failBuildOnCVSS>
    <!-- 聚合模式：一次扫全 reactor，报告合并 -->
    <aggregate>true</aggregate>
    <!-- 数据缓存目录（CI 持久化到 /root/.m2 避免每次重拉 NVD） -->
    <dataDirectory>/root/.m2/dependency-check-data</dataDirectory>
    <nvdValidForHours>24</nvdValidForHours>
    <suppressionFile>${maven.multiModuleProjectDirectory}/ci/dependency-check-suppressions.xml</suppressionFile>
    <!-- 国内 NVD API 慢：若有 nvdApiKey 通过 secrets 注入则加速，无则靠缓存 -->
    <nvdApiKey>${env.NVD_API_KEY}</nvdApiKey>
  </configuration>
</plugin>

<!-- SBOM：CycloneDX，0day 时 30 分钟内定位受影响服务 -->
<plugin>
  <groupId>org.cyclonedx</groupId>
  <artifactId>cyclonedx-maven-plugin</artifactId>
  <version>2.9.1</version>
  <executions>
    <execution>
      <phase>package</phase>
      <goals><goal>makeAggregateBom</goal></goals>
    </execution>
  </executions>
  <configuration><outputFormat>json</outputFormat><includeBomSerialNumber>true</includeBomSerialNumber></configuration>
</plugin>

<!-- 强约束：禁已知漏洞坐标（与 dependency-check 互补，编译期即拦） -->
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-enforcer-plugin</artifactId>
  <executions>
    <execution>
      <id>ban-vuln-deps</id>
      <goals><goal>enforce</goal></goals>
      <configuration>
        <rules>
          <bannedDependencies>
            <excludes>
              <!-- 示例：log4j 2.0–2.14.1 核弹级，全禁；fastjson 1.x 已换 2.x 也应禁 -->
              <exclude>org.apache.logging.log4j:log4j-core:[2.0,2.15.0)</exclude>
              <exclude>com.alibaba:fastjson:[0,1.2.83)</exclude>
            </excludes>
          </bannedDependencies>
        </rules>
      </configuration>
    </execution>
  </executions>
</plugin>
```

> 注：Dependency-Check 的 `check` goal 默认输出 HTML/JSON 到 `target/dependency-check-report.html`；CI 用 `aggregate` 模式跑一次即可，不必每模块重复。

**② 新建 `ci/dependency-check-suppressions.xml`（④⑤ 台账登记机制）**
对存量 Medium/Low 或暂无法升级的传递依赖，逐条 suppress，**必须含 `<notes>` 理由 + `<cwe>`/CVE + 复查日期**（对应文档 ⑤「缓解措施 + 台账标记高风险 + 定期复查」）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<suppressions xmlns="https://jeremylong.github.io/DependencyCheck/dependency-suppression.1.3.xsd">
  <!-- 示例：某传递依赖含 Low 漏洞，当前无补丁，走缓解 + 季度复查 -->
  <suppress>
    <notes><![CDATA[E4-SUP-001 | CVE-xxxx-xxxx | 低危，无补丁，WAF 已拦对应利用路径 | 复查 2027-01-15 | 责任人: xinfei]]></notes>
    <cve>CVE-xxxx-xxxx</cve>
  </suppress>
</suppressions>
```

**③ 新建 `.gitea/workflows/sca.yml`（②触发策略）**
套用现有 `build-check.yml` 的内网 clone 风格（`DEPLOY_HOST` 变量、`/root/.m2` 挂载、`/ci/maven-settings.xml`）：

```yaml
name: "SCA-依赖漏洞扫描（push/周巡/手动）"
on:
  push:
    paths:
      - '**/pom.xml'
      - '**/pnpm-lock.yaml'
      - '**/package-lock.json'
  schedule:
    - cron: '0 3 * * 1'   # 每周一 03:00 全量巡检
  workflow_dispatch: {}    # 发布前手动触发

env:                       # 与 build-check.yml 等现有 workflow 对齐：workflow 级统一定义，换机器只改这里
  DEPLOY_HOST: "192.168.20.130"

jobs:
  sca-backend:
    runs-on: ubuntu-latest
    env:
      SCA_FAIL_CVSS: "7"   # 门禁线：≥7.0 阻断
    steps:
      - name: 检出代码（内网 Gitea）
        run: |
          rm -rf ./* ./.??*
          git clone --depth 50 -b "${GITHUB_REF_NAME:-master}" "http://${DEPLOY_HOST}:3000/xinfei/xinfei-tms.git" .
      - name: Dependency-Check 聚合扫描
        run: |
          set -e
          mvn -B org.owasp:dependency-check-maven:check -s /ci/maven-settings.xml \
              -DfailBuildOnCVSS=${SCA_FAIL_CVSS} \
              -DdataDirectory=/root/.m2/dependency-check-data
      - name: 生成 SBOM（CycloneDX）
        run: mvn -B org.cyclonedx:cyclonedx-maven-plugin:makeAggregateBom -s /ci/maven-settings.xml
      - name: 归档报告与 SBOM
        run: |
          mkdir -p artifacts
          cp target/dependency-check-report.html artifacts/ 2>/dev/null || true
          cp target/bom.json artifacts/ 2>/dev/null || true
        # 实际 Gitea Actions 用 actions/upload-artifact 或 scp 到内网存储，按现有风格对齐

  sca-frontend:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        app: [xfwl-admin-ui-vue3, xfwl-mobile]
    steps:
      - name: 检出代码（内网 Gitea）
        run: |
          rm -rf ./* ./.??*
          git clone --depth 50 -b "${GITHUB_REF_NAME:-master}" "http://${DEPLOY_HOST}:3000/xinfei/xinfei-tms.git" .
      - name: pnpm audit（High 即失败）
        working-directory: ${{ matrix.app }}
        run: |
          npm i -g pnpm@9
          pnpm install --frozen-lockfile
          pnpm audit --audit-level high

  notify:
    needs: [sca-backend, sca-frontend]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - name: 周巡/异常通知（复用 C4 企业微信通道）
        run: |
          # 调企业微信机器人，附报告链接 + 新增漏洞数；具体 webhook 复用 C4 既有 secret
          echo "SCA 扫描完成，详见 artifacts / 企业微信通知"
```

**④ 前端 audit 接入 `build-check-fe.yml`（①工具链）**
在现有 `build-check-fe.yml` 每个前端 build 步之前，插入 audit（与 ③ 的 `sca-frontend` 二选一即可，建议保留 ③ 独立 job 以免拖慢前端发布）：

```yaml
      - name: 依赖审计（pnpm audit，High 即失败）
        working-directory: xfwl-admin-ui-vue3
        run: |
          pnpm install --frozen-lockfile
          pnpm audit --audit-level high
```

**⑤ 修复 SOP 落地（⑤五步法）**
建 `docs/需求文档/` 下漏洞台账（或 C4 看板），每条含：CVE / 组件:版本 / CVSS / 三源定级（AVD+NVD+CNNVD 取最高）/ 5×5 排序 / 修复动作（升级到 X.Y.Z 或 exclusions 排除或缓解）/ SLA / 责任人。EOL 无补丁项走 suppression + 缓解 + 定期复查，修复后重扫验证闭环。

**⑥ SBOM 归档与 0day SOP（⑥）**
每次发布（deploy-backend.yml / deploy-frontend.yml）后，将 `target/bom.json` 随发布版本归档；0day 爆发时：
```
grep -rl '"groupId":"org.apache.logging.log4j"' artifacts/bom.json   # 30 秒内定位受影响模块
```

**⑦ 周巡与看板（⑦）**
`sca.yml` 的 `schedule` cron 每周全量扫，`notify` job 推企业微信；未解决漏洞看板化（等级/组件/引入时间/责任人）。

**⑧ 落地注意（⑧）**
- 首次扫描大概率有存量 Medium/Low（Spring Boot 3.5.7/JDK21 较新但传递依赖深）——**只阻断 Critical/High（CVSS≥7），存量 Medium 用 suppression + 台账按 P2 SLA 消化，不要求首发清零**；
- NVD API 国内访问慢 → `dataDirectory` 持久化到 `/root/.m2`（runner 已挂载），首次拉取后缓存；周巡 job 不卡发布；
- 若迁阿里云效，其内置依赖检测可原生替代自建（对接 AVD 中文修复建议），届时删 `sca.yml` + 根 pom 插件即可。

**⑨ 可选增强（P2 评估）**
阿里《Java 开发手册》P3C 安全规约扫描插件，与现有 ArchUnit 门禁互补。

### 验收

- [ ] `.gitea/workflows/sca.yml` 存在；`push`（改 `pom.xml`）触发 `sca-backend` 成功跑出 HTML/JSON 报告；
- [ ] **门禁生效（关键）**：测试 commit 引入已知漏洞依赖（如 `log4j-core:2.14.1` 或 `fastjson:1.2.68`），`sca-backend` 因 CVSS≥7 **失败阻断**；suppression 中登记的项不阻断；
- [ ] `pnpm audit --audit-level high` 在某前端引入高危 npm 包时失败；
- [ ] 每次发布 `target/bom.json`（CycloneDX）随版本归档，且 `grep` 能定位组件；
- [ ] `ci/dependency-check-suppressions.xml` 存在，每条含理由 + 复查日期；
- [ ] 周巡 cron 触发后企业微信收到通知；
- [ ] 发布检查单含「无未处置 High 漏洞」项（对齐 69 E4 验收）。

### 依赖

- **无硬依赖**：E4 是 P1，独立于 P0 十一卡；根 pom 加插件不影响现有 `compile`/`auto-deploy` job（dependency-check 不在默认 lifecycle，需显式 `check` goal 才跑）。
- **注意点**：根 `pom.xml` 是共享文件，加插件前确认没有他人在途未提交改动（`git status` 甄别）；enforcer 的 `bannedDependencies` 若误伤现有合法依赖会导致所有构建失败，上线前先用 `-Denforcer.skip=true` 跑通再放开。

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| NVD 国内拉取慢/超时 | `dataDirectory` 持久化缓存 + `nvdValidForHours=24`；必要时配 `NVD_API_KEY` secret 加速 |
| 首次扫描误报/存量噪音 | suppression 机制 + 台账；不要求首发清零 |
| enforcer 误伤合法依赖 | 先 `-Denforcer.skip=true` 验证，逐步收紧 bans |
| act_runner 无外网拉 NVD | 预置 `/root/.m2/dependency-check-data` 数据副本，或改用内网 NVD 镜像 |
