## 1. 硬性规则（违反即失败）

### 1.1 动态路由开关（最高风险，禁止单独打开）

**禁止仅改 `isRouteGenerated` 初值、或注释守卫分支来"启用动态路由"。**

打开动态路由必须**同时**满足以下 4 个前提，缺一不可：

1. **后端已实现** `GET /api/v1/menus/routes`（按角色/权限过滤）及菜单 CRUD；
2. **`sys_menu` 表结构已迁移**到前端契约（见 §1.7 字段清单）；
3. **`mock/menu.mock.ts` 的 `routes` 已换成心飞业务菜单**（或确认后端接管后删除该 mock）；
4. **前端路由命名冲突已清理**（见 §1.4）。

开关变更必须同步修订本文档，并经人工确认后才可提交。

### 1.2 菜单结构

- 菜单层级只由**后端 `sys_menu` 的 children** 决定；前端**禁止**写菜单分组映射/归组函数（`MENU_GROUP_MAP` / `groupFlatMenus` 已删除，勿恢复）。需要分组就在后端配目录层级。
- 静态路由子路由 `path` **一律绝对路径**（如 `/order` 挂在 `/order-center` 下）；**菜单层级变化不得改变 URL**（旧书签/深链兼容，2026-10-11 定案）。
- 叶子菜单只有一层 `el-menu-item`；**禁止** AppLink / router-link 包裹（避免 a>li 双层留白），`@click` 直接 `router.push`（外链 `window.open`）。

### 1.3 布局取数（Mix / Top / Double 布局）

- 侧边栏/顶栏取数**必须**走 `src/layouts/composables/useLayout.ts` 的 `flattenSidebarRoutes(permissionStore.routes)`。
- **禁止**直接 `permissionStore.routes.filter(...)` 作为 Mix / Top / Double 布局的顶部菜单：后端动态菜单以 `path:"/"`、无 `meta.title` 的根 Layout 包裹全部业务菜单，不拍平会出现**空白顶级菜单项**。
- `setMixLayoutSideMenus` 只查找顶级路由（`permission.ts:43-46`）；涉及根壳结构时必须**先拍平再查找**，否则 Mix / Double 次级侧边栏为空。
- **勿删** `flattenSidebarRoutes` 拍平逻辑。

### 1.4 路由 name 唯一性

- 动态子路由 `name = menu.name`（`permission.ts` `buildChildRoutes`）；**禁止**与静态 `constantRoutes` 已有 name 重复：`Dashboard / Order / OrderCargoEdit / Transport / Task / PickupDispatch / DriverJob / Dispatch / Monitor / Alarm / Truck / TruckType / Fleet / Driver / TransportLine / TransportLineType / GoodsType / User / Role / Menu / Dept / Org / Station / Dict / Config / Notice / Log / Tenant / Area / Profile / BigScreen / FormShare`。
- 同类菜单之间 name 也**必须唯一**；重复 name 会导致 `router.addRoute` 告警跳过、按 name 导航（`useMixMenu.navigateToFirstMenu`）失效、`removeRoute` 误删。
- 新增页面菜单的 `routeName` 用派生规则（如 `/system/user` → `SystemUser`），禁止用中文名或随意手填。

### 1.5 菜单管理页与 mock

- `mock/menu.mock.ts` **仅 dev 演示**，不参与生产构建；其 `menus/routes` 当前为模板演示菜单，**禁止引用为业务菜单基线**。
- 菜单管理页增删改后 `refreshUserRoutes()` 失败属预期（§0），禁止绕过守卫或改静态路由去"实现"菜单管理。

### 1.6 外链与图标

- 外链-新标签页：菜单**无 component** + `meta.externalUrl`（或 `path` 直接外链）；外链-内嵌：`component="iframe"`（由 `src/views/iframe.vue` 承载），禁止改名/改路径。
- 图标为空时由 `LayoutMenuIcon.vue` 自动 fallback 为 Element Plus `Document`，不显示黑色方块；禁止手写空图标占位。

### 1.7 后端菜单契约

- `sys_menu` 表结构与接口 DTO **以 `src/api/system/menu/types.ts` + `src/enums/business.ts` 为准**：
  `type`（C-目录 / M-菜单 / E-外链 / B-按钮，**字符串**）、`visible`（1 显示 / 0 隐藏）、`scope`（1 平台 / 2 业务）、`routeName`、`routePath`、`externalUrl`、`params`、`perm`、`redirect`、`keepAlive`、`sort`、`component`、`children`。
- **禁止**后端数字枚举（`Constant.MenuType` 0/1/2）与前端字符串 `C/M/E/B` 混用；后端实现时统一为字符串。

### 1.9 按钮权限（`type='B'`）粒度与双控约定（2026-10-17 补强）

- **按钮权限即 `sys_menu` 中 `type='B'` 的行**，`perm` 同时驱动**前端** `v-hasPerm`（隐藏按钮）与**后端** `@SaCheckPermission`（拒绝越权调用）——双控缺一不可，前端隐藏不是安全边界。
- **命名规约**：`perm` 按「域:实体:动作」三段，动作取 `list`/`create`/`update`/`delete`/`export`/`import`/`change-status`/`assign` 等。示例（`V20261016_1000` 实测）：应用管理菜单 `sys:app`，按钮 `sys:app:list / create / update / delete / change-status`；部门 `sys:dept:list / create / ...`。
- **按钮行挂载**：`parent_id` 指向所属菜单行（`type='M'`），`path/component` 为空、`visible` 不影响菜单显示、`sort_value` 控制按钮顺序。
- **新增受细粒度保护的接口**：① 接口挂 `@SaCheckPermission("sys:xxx:create")`；② 在 `sys_menu` 登记对应 `type='B'` 行（`perm` 与注解一致）；③ `sys_role_menu` 给角色授权；④ 前端按钮加 `v-hasPerm="'sys:xxx:create'"`。四步缺一则该按钮对该角色不可见 / 调用被 403（未授权角色 403、按钮不可见，见《15》§〇 DoD）。
- **ADMIN 特殊**：`code='ADMIN'` 或含 `*` 权限短路返回 `*`（`StpInterfaceImpl`），前端据此放行全部，无需逐按钮授权；`sys_role_menu` 仍落库仅为"角色管理勾选树完整"（§第3步注记）。

### 1.11 按钮权限字段级清单（逐子域 `sys_menu.type='B'` 的 `perm` 命名，2026-10-17 补全）

> **全量真源＝`sys_menu` 库表 + 代码 `@SaCheckPermission` 注解双向核对**（《62》§11.5「权限码逐条取自代码、非推测」纪律；2026-10-16 已核验 41 个权限码 100% 落库、零孤儿）。本表为**管理端 13 个子域（system/）的按钮命名规约**，是新增按钮的模板基线；业务域（订单/调度/在途/档案）按钮沿用同一 `域:实体:动作` 三段式。

| 用户 user | `sys:user` | `sys:user:list / create / update / delete / reset-password / assign-role / change-status` |
| 角色 role | `sys:role` | `sys:role:list / create / update / delete / assign-menu / assign-dept` |
| 菜单 menu | `sys:menu` | `sys:menu:list / create / update / delete` |
| 部门 dept | `sys:dept` | `sys:dept:list / create / update / delete` |
| 机构 org / 网点 station | `sys:org` / `sys:station` | `sys:org:list / create / update / delete`（station 同构） |
| 字典 dict | `sys:dict` | `sys:dict:list / create / update / delete / export`（含字典项 `items` 增删改） |
| 应用 app | `sys:app` | `sys:app:list / create / update / delete / change-status` |
| 通知 notice | `sys:notice` | `sys:notice:list / create / update / delete / publish` |
| 日志 log | `sys:log` | `sys:log:list / connect-status / delete / export` |
| 租户 tenant | `sys:tenant` | `sys:tenant:list / create / update / delete / assign` |

### 1.12 菜单运维异常处置清单（2026-10-17 补全）

| 现象 | 根因 | 处置 |
|---|---|---|
| 侧边栏空白 | 角色未绑 `sys_role_menu`；或新页只建 `.vue` 未在 `sys_menu` 登记 | 查 `sys_role_menu` 授权；按 §1.7 在 `sys_menu` 登记 `type=M` 并用 `sys_role_menu` 绑角色 |
| 菜单改动后不生效 | 无进程内缓存，需刷新 | **刷新页面即生效，无需重启**（xfwl-auth 无 `@Cacheable`/Caffeine） |
| 接口 403 但菜单可开 | 有菜单无按钮权限 / `perm` 未对齐 | 核对 `sys_menu` 按钮行 `perm` 与 `@SaCheckPermission` 一致；角色绑按钮 |
| 按钮可见但接口 403 | 仅前端隐藏未过 `@SaCheckPermission` | 接口补 `@SaCheckPermission`（后端是安全边界） |
| 权限码孤儿（接口存在注解、库无按钮行） | 新增接口只加注解忘了登记 | 补 `sys_menu` 按钮行（§1.9 四步） |
| 被误认"缓存问题" | — | 一律先查 `sys_role_menu` 授权，勿盲清缓存 |

### 1.13 多角色批量初始化授权（2026-10-17 新增需求）

- **需求**：角色蓝图（《62》§10.2 的 ADMIN/调度/运营/车队长/财务/审计/网点/客服等）一次性批量初始化 `sys_menu` 授权基线，避免逐菜单手工勾选遗漏。
- **落点**：`sys_role_menu` 幂等 INSERT（按 role + 允许的顶级域/菜单 id 段批量授权），SQL 走 `sql/` 幂等迁移；dev 库授权修正先 `mysqldump` 备份再执行。
- **约束**：ADMIN 运行期短路 `*`，落库仅为角色管理勾选树完整；运营/财务等权限敏感角色须按 §1.8 行级基线逐角色核验，**不默认给兜底全权**（SYS-02 最小化原则）。
