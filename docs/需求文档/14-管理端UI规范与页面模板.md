## 第 1 章 设计原则（最高优先级）

1. **只用 Element Plus 组件，不写裸样式**：布局用 `el-container`/`el-row`/`el-col`，列表 `el-table`，表单 `el-form`，弹窗 `el-dialog`，下拉 `el-select`，标签 `el-tag`，分页 `el-pagination`。**禁止**手写 `<div>`+`<style>` 替代组件做布局/按钮/卡片。
2. **设计 Token 全集中**：颜色/间距/字号/圆角/阴影只允许引用 `src/styles/tokens.scss`（§2）或 Element 主题变量，**禁止页面内硬编码 hex / px**（图表色与地图浮层除外，见 §5/§6）。
3. **品牌主色全端统一**：主色 **`#FF0033`**（心飞红，与移动端 `--c-primary` 同一品牌色）。**废弃**冲突色：Element 默认 `#1890ff`、`#409EFF`、`#E05635` 及旧主色 `#2B6CFF`/`#E15536`（现状硬编码冲突色）。落地方式：`element-plus-vars.scss` 覆写 Element Plus 主题色 map（**已落地 #FF0033**，2026-10-14 实测 `element-plus-vars.scss` primary base 即 #FF0033），全局替换硬编码色为变量。
4. **结构走模板**：每类页面套用 §4 标准骨架，不允许自由布局。
5. **三态必做**：列表/查询页必须有 加载中 / 空 / 错误 三态（`v-loading` / `el-empty` / 重试按钮）。
6. **图表与地图遵循专项规范**（§5/§6）：图表色板取自 Token，地图浮层/聚合按统一交互。

## 第 3 章 全局结构规范

### 3.1 页面骨架（统一容器）

```
<template>
  <div class="page">                     <!-- 背景 --c-bg，内边距 --s-4 -->
    <div class="page-header">            <!-- 标题 + 主操作按钮(右) -->
      <span class="page-title">订单管理</span>
      <div><el-button type="primary">新建</el-button></div>
    </div>
    <el-card class="filter-card">…</el-card>   <!-- 筛选区 ≤3 行 -->
    <el-card class="table-card">…</el-card>    <!-- 表格 + 分页 -->
    <el-dialog>…</el-dialog>                    <!-- 弹窗表单 -->
  </div>
</template>
```

- 路由由后端动态下发（定案 `D-42`）：**实装口径**＝`MenuAPI.getRoutes()` → `GET /api/v1/menus/routes`（xfwl-auth `MenuController`，按 `sys_role_menu` 授权过滤，超管全量）→ `stores/permission.ts` 的 `buildRoutes` / `filterRoutes` 映射 `@/views/${path}.vue` 并注册。**新增页面必须在 `sys_menu` 登记路由与按钮 `perm`、用 `sys_role_menu` 绑角色**，否则菜单不显示；改完刷新页面即生效（无进程内缓存）。
- **列表页实装布局与间距（2026-10-19 全站统一，真源 `src/styles/page.scss` + `theme.scss`）**：上图为设计语义，实际类名体系为 `page-container > el-card.page-content > (page-toolbar → page-table-wrapper > el-table → page-pagination)`，卡片 body 是 `grid-template-rows: auto minmax(0,1fr) auto` 三行弹性布局。**间距全部由全局变量驱动，禁止页面内硬编码 px 覆盖**：
  | 间距项 | 值 | 来源 |
  |---|---|---|
  | toolbar ↔ 表格（上侧工具栏） | `var(--page-gap)` = 10px | `page.scss` `.page-toolbar{margin-bottom:var(--page-gap)}` |
  | 表格 ↔ 底部操作栏/分页 | `var(--page-gap)` = 10px | 全局继承；底部 toolbar 局部只允许 `margin-top: var(--page-gap)` 对齐 |
  | 页面四周 / 卡片间 | `var(--page-padding)` = 10px | `theme.scss` |
  | 卡片内边距 | 12px 16px | `page.scss` `.page-content .el-card__body` |
  > 2026-10-19 已按此口径清理全站偏差：`order/exception`、`transport` 两页底部操作 toolbar 的硬编码 `margin-top:12px` 已改 `var(--page-gap)`。基准参照页＝会员管理 `member/index.vue`。
- 请求统一走 `src/utils/request`（Axios，`baseURL=import.meta.env.VITE_API_BASE`：开发 `/dev-api`、生产 `/prod-api`，代码内 url 已带 `/api`）。**实装口径**：请求头字段为 `token`（非 `Authorization`），无 `refreshToken`，401 清 token 重登。`code!==0` 判失败。**禁止裸 `fetch`**。

### 3.2 统一反馈（禁止自造）

| 场景 | 组件 | 说明 |
|---|---|---|
| 整页加载 | `v-loading` + `element-loading-text="加载中…"` | 列表/详情首次加载 |
| 空态 | `<el-empty description="暂无数据">` | 数据为空 |
| 错态 | `<el-empty>` + 重试按钮（调同一请求） | 请求失败 |
| 成功/失败提示 | `ElMessage`（success/error） | 提交/操作反馈（Vue3 组合式 API 显式导入；禁用 Vue2 的 `this.$message` 写法） |
| 确认弹窗 | `ElMessageBox.confirm` | 删除/取消/改派等危险操作（禁用 Vue2 的 `this.$confirm` 写法） |
| 分页 | `el-pagination`（`page`+`pageSize` 驼峰——全工程 CrudTable/各页实测口径，`total` 后端返回） | 统一布局 `total` + `pager` + `sizes` + `jumper` |

### 3.3 列表页交互约定

- 筛选区（`el-card`）：≤3 行；状态筛选用 `el-select`（数据源走 `CommonController common/*/simple`，**禁止硬编码数字**，见《数据字典与枚举口径》红线）；时间用 `el-date-picker`（datetimerange）；查询/重置按钮。
- 表格：行高默认；列顺序按任务卡"字段/操作清单"；操作列固定右侧（`fixed="right"`）；超长文本 `show-overflow-tooltip`。
- **列对齐口径（2026-10-16 统一，全站已按此执行）**：文本列默认左对齐（不写 `align`）；状态/类型等枚举标签列 `align="center"`；数字/金额/耗时列 `align="right"`；操作列 `align="center"` + `fixed="right"`。新增列照此，存量页面禁止再混用 `align="left"`。
- 批量操作：`el-table` `@selection-change` 记录选中，批量按钮仅在选中数>0 时可用（主操作唯一）。

### 3.4 侧边栏菜单规范（平级铺开，2026-10-11 最终定案）

> **决策变更**：本日早些时候曾按联云 TMS 做前端归组（`groupFlatMenus()` + `MENU_GROUP_MAP`），用户最终拍板**撤销**——`el-sub-menu` 渲染的分组标题层 `el-sub-menu__title` 占纵向空间、视觉冗余。以下为现行规范，勿恢复前端归组。

- **结构**：菜单**严格按后端 `sys_menu` 下发结构原样渲染**，`permission.ts` 的 `generateRoutes()` 直接 `buildRoutes(routeData)`，前端不做任何归组、不生成 `el-sub-menu` 分组标题。`groupFlatMenus`/`findGroupByPath`/`MENU_GROUP_MAP` 已删除。**将来需要业务分组时，正解是在后端 sys_menu 配目录层级（children 树），禁止在前端硬编码分组映射。**
- **根布局壳拍平（`useLayout.ts` 的 `flattenSidebarRoutes()`，2026-10-11 补，logo 下方空白/折叠整组弹层的根因）**：后端动态菜单下发的是**一个 `path:"/"`、无 `meta.title` 的根 Layout，children 挂全部业务菜单**。该壳只用于路由套 Layout，**不得在侧边栏渲染成 `el-sub-menu`**（否则展开态多一个 40px 空标题行=logo 下空白，折叠态全部菜单收进一个多余 popper）。侧边栏/顶栏取数必须经 `flattenSidebarRoutes(routes)`：把「无标题 + 有可见 children」的纯容器拍平，children 提升为同级并用 `path.resolve` 补全绝对路径；**带标题的真实目录分组保留**（可折叠）。此函数只改菜单渲染数据，不动路由注册，勿删。
- **视觉（`layout.scss`，2026-10-11 二次修订：一级/二级必须可辨）**：
  - 一级目录标题（`> .el-sub-menu > .el-sub-menu__title span`）：**15px / font-weight 600 / `var(--el-text-color-primary)`**，高 40px、图标 18px。
  - 二级叶子项（`.el-sub-menu .el-menu .el-menu-item`）：**14px / 常规字重**，高 **38px**、左缩进 **40px**、图标 **16px**。
  - 层级只靠**字号字重 + 缩进 + 间距**承载：顶级条目之间 `margin-bottom:4px`（组内 0），**不给二级加背景色、不加引导竖线**（试过，浅色底变量在经典蓝/暗黑主题下不适配，且视觉比模板原生脏）。
  - 深色主题（`html.sidebar-color-blue` / `html.dark`）下一级标题**回退 `var(--menu-text)`**，不套用浅色主题的深字色，否则深底不可读。
  - `.el-menu` 与 `.el-scrollbar__view` 顶部 `padding:0`（消除 logo 与首项之间空白）；选中菜单项左侧 3px 主色竖条（仅侧边栏）。**已删除早期归组方案遗留的 `.el-sub-menu__title{28px…pointer-events:none}` 死样式**。
- **Logo（`LayoutLogo.vue`，2026-10-11 修订）**：图标按折叠态取尺寸——展开 **32px**、折叠 **24px**（`:class="collapse ? 'w24px h24px' : 'w32px h32px'"`，**不要用 `md:` 视口断点**，侧栏宽度和视口宽度无关）；标题 **16px / 600 / letter-spacing 0.5px**。早期统一 20px 在 210px 侧栏里偏小，用户明确要求放大。
- **结构约定（`LayoutSidebarItem.vue`）**：叶子菜单只有一层 `el-menu-item`，不使用 AppLink/router-link 包裹层；点击由 `el-menu-item @click` 直接 `router.push`（外链 `window.open`），激活态由 el-menu 的 `index` + `default-active` 承担，禁止 `a>li` 双层嵌套造成留白。
- **图标约定（`LayoutMenuIcon.vue`）**：icon 为空时自动 fallback 为 Element Plus `Document` 默认图标，不显示黑色方块。
- **发布缓存**：nginx 对 `/`、`/index.html`、SPA fallback 均下发 `no-cache,no-store`，带 hash 的 js/css immutable 1 年；部署后页面仍旧先 Ctrl+Shift+R 硬刷新，勿误判为部署失败。
- 三套主题（浅色白 / 经典蓝 / dark）自动适配；想要联云蓝黑风在设置切 `sidebarColorScheme: classic-blue`。

### 4.2 详情抽屉（订单/运单/任务详情；2026-10-15 修订）

### 4.3.1 交互载体与二级弹层规范（2026-10-15 拍板）

**三级载体分工**（全站统一，勿混用）：

| 载体 | 承载 | 现状实例 |
|---|---|---|
| `el-dialog`（居中） | 写操作：新增/编辑/动作表单（≤10 字段） | 基础资料 CRUD、system 全域、新建订单 |
| `el-drawer`（居右） | 读操作：详情浏览 | 订单/任务/运单/司机/车辆/线路详情 |
| 整页路由 | 深流程：嵌套 CRUD / 长表单（>15 字段）/ 地图 | 订单货物 cargoEdit、动态表单设计器 |

**二级弹层决策规则**（从详情抽屉再往下一层，四模式）：

| 场景 | 载体 | 要点 |
|---|---|---|
| 详情抽屉发起"写"动作（派单/改派/改价/取消/审批） | 居中 `el-dialog` | 宽 420~560px；列表行与抽屉触发**同一个弹窗组件**（props 传 row），勿写两份 |
| 详情抽屉跳"关联对象浏览"（订单→运单→司机） | 二级 `el-drawer` | 宽 420px + `modal-class` 遮罩降浅做侧滑面板感；仅限纯浏览链 |
| 详情抽屉发起"多字段编辑"（10~15 字段） | 抽屉内视图切换 | 内容切表单 + 顶部"返回详情"；>15 字段升整页 |
| 嵌套 CRUD / 地图 / 向导式长流程 | 整页路由 | 禁止弹窗套弹窗承载嵌套 CRUD（参照 cargoEdit 整页模式） |

**实现硬规则**：

1. 二级弹窗必须 `append-to-body`（防 z-index 被抽屉吞掉、遮罩错位——Element Plus 高频坑）。
2. 数据闭环：二级弹窗提交成功后须重拉一级抽屉详情（`getDetail(id)`），禁止让用户手动刷新。
3. 🔴 **禁止三层嵌套**（抽屉 > 弹窗 > 弹窗）；双层抽屉仅限纯浏览链且 ≤2 层。
4. 危险操作（取消/删除/改派）一律走 `$confirm` 二次确认。
5. 新页面交互方案不在本表内时，默认按"写=dialog、读=drawer、深流程=整页"兜底，勿自创新形态。

### 4.3.2 二级弹层视觉规范（2026-10-15）

**① 尺寸阶梯**（宽度按层级递减，形成视觉主从）：

| 层级 | 形态 | 标准宽度 | 备注 |
|---|---|---|---|
| L1 详情抽屉 | `el-drawer` | `min(640px, 92%)` | 存量 620/660px 页面统一时机顺带收敛，不专项改 |
| L2-A 动作弹窗 | `el-dialog` | 轻确认 420px / 标准表单 520px / 重表单上限 720px | 新建订单属重表单档；指派类属轻确认档 |
| L2-B 关联抽屉 | `el-drawer` | 420px | 必须窄于 L1，凸显层级递进 |
| 弹窗高度 | 自适应 | body `max-height: 70vh` + 内部滚动 | 超长表单禁撑爆视口 |

**② Z 轴与遮罩**：

- z-index 一律由 Element Plus 自动管理（`append-to-body` 后递增），**禁止手写 z-index**。
- L2-A 动作弹窗遮罩用 EP 默认（叠加后整体压暗=聚焦感，保留）。
- L2-B 关联抽屉遮罩**必须降浅**：`modal-class="xfwl-modal-light"`（全局类，`rgba(0,0,0,.2)`，dark 主题用主题变量适配），营造"侧滑面板"而非"二次遮罩"。

**③ 标题与层级指示**：

- L2-A 标题 = 动作名 + 对象标识：`改派 · 订单 XD20261015-0001`（16px/600，EP 默认 title 样式）。
- L2-B 抽屉标题带路径：`订单详情 / 运单详情`，让用户知道自己在第几层。
- L2-C 视图切换顶部必须有"← 返回详情"文字按钮。

**④ 间距与按钮区**：

- 弹窗 body 内边距用 EP 默认；分段表单段标题 14px/600、段间距 12px（参照 order 页 `order-detail__title`）。
- footer 按钮右对齐、间距 12px：主操作右一（`type=primary`）、危险操作用 `type=danger` 或红色 `$confirm` 确认、次操作 default。
- 提交按钮必带 `:loading` 防双击；成功后 `ElMessage.success` 顶部居中弹出，禁止在弹窗内自绘成功态。

**⑤ 状态与反馈**：

- 校验失败：行内红字 + `scroll-to-error` 定位首个错误项，不用 message 报错。
- 弹窗内异步数据（如选择车辆/司机列表）用 `v-loading` 蒙层。
- L2 成功关闭后 L1 重拉数据期间，抽屉整体 `v-loading`，防闪烁跳变。

**⑥ 动画与主题**：

- 入出场动画一律 EP 默认（dialog 淡入缩放 / drawer 右侧滑入 300ms），**禁止自定义时长或曲线**。
- 三套主题（浅色白/经典蓝/dark）自动适配：弹层颜色全部走 EP 主题变量，**禁止硬编码色值**；品牌红仅出现在主按钮/危险确认，不做大面积铺色。

**⑦ 公共样式锚点**（全局样式表统一定义一次，页面零散 CSS）：

```scss
// 二级关联抽屉浅遮罩（§4.3.2-②）
.xfwl-modal-light { background: rgba(0, 0, 0, 0.2); }
// 超长弹窗内容滚动（§4.3.2-①），dark 主题自动适配
.xfwl-dialog-body-scroll { max-height: 70vh; overflow-y: auto; }
```

## 第 5 章 图表规范（ECharts ^6.1.0，以 `package.json` 实测为准）

1. **色板**：只允许 §2.3 八色，`color:['#FF0033','#00B42A','#FF7D00','#F53F3F','#8E44AD','#13C2C2','#FFC53D','#86909C']`，禁止自定义色。
2. **轴与网格**：`textStyle.color: var(--c-text-2)`；`splitLine` 用 `#E5E6EB`；`axisLabel` 字号 12px；`grid` 留出图例空间。
3. **图例**：`legend` 必配（顶部，`type:'scroll'`）；单系列可省。
4. **空态/加载**：图表容器数据为空显示 `<el-empty>` 覆盖层（不渲染空白 canvas）；加载用 `v-loading`。
5. **Tooltip**：`trigger:'axis'`（多系列）/`item`（单系列），`valueFormatter` 统一单位（元/趟/件/公里）。
6. **数据口径**：图表数值一律来自接口聚合（dashboard 已接 `src/api/dashboard/index.ts` overview 真实数据；新增图表禁静态值）；单位/口径与《数据字典与枚举口径》一致。
7. **禁止**：引入第二个图表库（Chart.js/Highcharts）；echarts 实例不销毁（Vue3 写法：`onBeforeUnmount` 中 `dispose`）。

---

## 第 6 章 地图规范（百度地图 JS API GL）

1. **库**：`vue-baidu-map-3x` 或直引 GL JS 脚本；**不引第二地图库**（AMap/Leaflet）。`location.ak` 为占位值，上线前替换真实 key（开发期测试 key / mock 数据先行）。
2. **坐标**：后端统一存储 **WGS84（GPS/北斗原始）**；管理端百度地图显示层做 WGS84→BD-09 转换，移动端小程序腾讯地图（GCJ-02）做 WGS84→GCJ-02 转换，转换工具统一走 `common/utils/coord.ts`（见 BA-19）。
3. **浮层交互**：地图浮层统一 `el-card`（白底、圆角 `--r-md`、阴影 `--shadow-card`）；点选标记 → 浮层展示（车牌/状态/最新时间）；浮层可关闭。
4. **聚合**：车辆/订单点多于 50 用 `BMapGL.MarkerClusterer` 聚合；点击聚合下钻一级。
5. **轨迹回放**：`polyline`（主色 `#FF0033` 系）+ 播放进度条；起点/终点 Marker 区分（绿=起点，红=终点）；轨迹点串来自 `GET /api/netty-service/trace/replay?businessId=&type=`。
6. **禁**：无底图时画 ECharts 折线冒充地图；坐标写死/手填。
