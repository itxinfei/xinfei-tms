## 第 1 章 项目约束与红线（宪法级，必须最先读）

> **本章是最高优先级约束。任何开发任务都必须先满足本章，违反本章的改动一律视为不合格、必须回退。**

### 1.1 技术栈硬约束（不可变更）
1. **JDK 固定 25 LTS（Eclipse Temurin）**，不得降级到 8/11/17/21，不得在未评估情况下升级到 25 之外的更高功能版（非 LTS 或新 LTS 需人工确认）。**`pom.xml` 通过 `<java.version>25</java.version>`（Spring Boot parent 自动映射为 `release`）锁定；运行时 Dockerfile 基础镜像 `eclipse-temurin:25-jre-jammy`，CI 镜像 `maven:3.9.9-eclipse-temurin-25`**。（**2026-10-20 修订**：由 21 LTS 升级至 25 LTS，经人工确认；原"不得升级到 22+"条款废止。）
2. **后端依赖锁定到升级后基线**（见 §2.1）：全栈已迁至 JDK21/SB3.5/Cloud2025.0/Alibaba2025.0.0.0 等，**未经人工显式同意，禁止在基线之上再擅自升级依赖**（含 Spring Boot、Cloud、Alibaba、MyBatis Plus、Druid、Shiro、Drools、Lombok、FastJSON2 等）。（**2026-10-08 修订**：原"禁止升级任何依赖"已废止——全栈升级本身即依赖升级，本条款现约束"不超出已定基线的额外升级"。**2026-10-10 修订**：基线由 SB3.3/Cloud2023 上调为 SB3.5/Cloud2025.0，经人工确认。）
3. **安全 CVE 随全栈升级一并解决**：FastJSON 1.x→2.x、Shiro 升级至安全版本等随第2条迁移自然消除；升级后若仍有未覆盖的高危 CVE，须登记并评估。（**2026-10-08 修订**：原"安全问题不考虑"已废止——见《12》第3条。）
4. **业务代码不降级/不重写**：保持现有分层（controller / service / service.impl / mapper / entity）与 MyBatis Plus 用法；使用 jakarta.* 命名空间（非 javax.*）。（**2026-10-10 豁免注**：本条与 §1.3 第 10 条在**「全量重构专项」（定案 `D-61`）任务内解除限制**——重构须遵守 D-61 行为护栏（对外行为等价：接口契约以《08》为准、状态编码以《07》为准、回归以《27》为准）；专项外本条照常生效。）

### 1.2 架构与边界红线
5. **新增功能优先复用现有能力**：三端 REST API（`xfwl-web-customer/driver/courier`）已存在，移动端直接调用，**后端能不改则不改**。
6. **后端"未实现的中间件"是用户路线图，不是缺失 bug**：MongoDB/HBase/Spark/Hive/ES/RocketMQ/MapStruct/Sentinel/SkyWalking/XXL-JOB 等，当前未落地是"计划内"，**不得把它们当成问题去补齐或"顺手"引入**。
7. **网关 = Spring Cloud Gateway**（模块 `xfwl-gateway`，包路径 `com.xinfei.tms.zuul`，已完成重写，见定案 `D-61` ③）——认证/登录校验由网关 `SaTokenConfigure` 承担，**无 Sentinel**。
8. **模块职责严格不越界**：订单只在 `xfwl-oms`、调度只在 `xfwl-dispatch`、作业只在 `xfwl-work`、基础数据只在 `xfwl-base`、轨迹只在 `xfwl-netty`。新增实体/接口放到对应模块，不跨模块写业务。

### 1.3 开发行为红线（AI 编码代理最易犯的错误）
10. **禁止"顺手"重构**：不重命名既有类/方法、不改既有接口签名；**「管理端 Vue3 升级专项」任务下允许改动 `xfwl-admin-ui-vue3` 源码与结构**，非专项仍不得随意重构 `xfwl-admin-ui-vue3`（管理端）既有文件，除非任务明确要求。（**2026-10-10 豁免注**：**「全量重构专项」（定案 `D-61`）任务内系统性重构获得授权**，豁免范围与行为护栏见 `D-61`；专项外本条照常生效。）
11. **禁止重复造轮子**：轨迹、鉴权、坐标/距离计算、状态机、运费等已有实现，新增功能必须调用既有实现；不得另写一套。
12. **禁止硬编码**：cron、阈值、地图 Key、坐标等配置必须外部化到 `application.yml` / Nacos / 配置文件；不写死在 Java/JS 中。（2026-10-10 起 **`bootstrap*.yml` 已废止**，配置加载姿势见 §2.1.1「配置加载口径」。）
13. **禁止破坏编译/契约**：每次改动后必须保证受影响的模块 `mvn -o -q compile` 通过（本地用 JDK 21 LTS）；对外接口字段变更须同步更新本文档 §5、§6。（**2026-10-08 修订**：编译 JDK 由 1.8 改为 21。）
14. **先读后写**：改动任何文件前，必须先用 Read/搜索确认其现状与调用关系；禁止凭记忆或猜测写代码。
15. **跨服务只传 DTO，禁止 entity 泄漏**（2026-10-10 R2④ 定案）：Feign 方法签名、返回值、`@RequestBody` 一律使用 `xfwl-service-*-domain` 中的 DTO，禁止出现业务模块 entity 类型；提供方 Controller 经 MapStruct Converter 转实体。契约 domain 内**禁止放置/继承 entity 副本**（曾存在与业务模块同包同名的 Order/AddressBook/Member 副本，已删除），DTO 不得 `extends` entity。`detail` 类查询直接返回 DTO，鉴权失败/不存在返回 null，消费方判空；禁止"Feign 声明裸实体、提供方返回 `Result` 包裹"的错配。

### 1.4 明确不做的"花架子"（本期一律不启动）
- 不盲目上 MongoDB / HBase / Spark / Hive / Elasticsearch / RocketMQ / XXL-JOB / Sentinel（路线图里有，但当前无对应痛点）。
- **管理端 `pd-admin-ui` 升级到 Vue3 列为本期专项**（目标栈：Vue3 + Vite + Element Plus + Pinia + ECharts，取代既有 Vue2.6 + Element UI 2.12 + Vuex 3 + Webpack 4；**版本现值以 `xfwl-admin-ui-vue3/package.json` 为准，见 §2.2 校正注**）。纯 UI 迁移不再视为"零收益"——它解除技术债：Webpack4/OpenSSL3 构建阻断（Node17+ 必现 `ERR_OSSL_EVP_UNSUPPORTED`）、Vue2 已 EOL（2023-12）、响应式与组合式 API 红利、为后续移动端同源复用打底。
- 不建重型 WMS（波次/上架策略/AGV）、不建多租户 SaaS、不建复杂 BI。**注意**：联云对标后新增的**轻量仓内作业与分拣域（§6.25 ASS/WMS-02）**属分拣/PDA 拣货能力，与"重型 WMS"不冲突；**冷链（§6.26）与充运（§6.27）也已按用户决策纳入**（原"不做冷链"口径已于 2026-10-08 废止）。
- 不对接外部厂商 / 三方物流 API（EDI/ERP/顺丰·三通一达/多式联运/国家合规）—— 本项目为自营 / 加盟运输管理，业务模式不涉及（详见 §6.9）。
- 不引入 GraphQL、不引入微服务网格、不做容器编排改造（除非用户单独指令）。

### 1.5 需求优先级定义

| **P1** | 重要补齐，明显提升时效/成本/差错 | 功能可用 + 数据正确 |
| **P2** | 增强/按需，出现真实痛点再做 | 单点验证通过 |
| **路线图** | 仅规划，本期不做 | — |

> 三者同属 P0 大档，退出标准与本表 P0 一致；R6-1/2/3/5 已于 2026-10-08 EC-01 口径统一降为 P1 限期补、不阻塞 M1，不再标 P0c。

### 1.6 当前阶段工作定调（🔴 2026-10-11 用户拍板，当前最高优先执行口径）

> 背景：项目处于内网 dev（宿主 192.168.20.130）、半成品、无真实用户、不上线。用户明确：开发阶段不为安全复杂度买单，全部精力压向"管理端能看到、能用"的交付。

1. **当前唯一主战场 = 后台管理系统 `xfwl-admin-ui-vue3`**：按《55-功能需求详细规格》与《14-管理端UI规范与页面模板》《16-管理端Vue3升级专项实施规范》，把管理端**功能做全、做完，页面设计好、交互闭环**。
   - 单个功能/页面的验收闭环 = **写完 → 提交 → 构建部署 → 浏览器可见可用**（部署：服务器 `bash /data/xinfei-deploy/deploy-fe.sh admin`）。
   - 移动端、后端的任务排序一律以"服务管理端演示闭环"为依据；**管理端需要的接口优先打通，后端不为架构完美阻塞页面**。
2. **dev 阶段效率优先，不做上生产才需要的安全功课**：
   - MySQL / Redis / RabbitMQ / Nacos 等中间件 dev 口令统一 `123456`，允许以 `${ENV:123456}` 默认值直接写入 `application.yml` / compose；不再要求密钥外置、0600 env 文件、dev 口令轮换。
   - 不为 dev 新增额外安全层（Same-Token 深化、入站加固、口令复杂度、回调白名单预配等一律不主动做）。
   - 已落地的 Sa-Token 登录、网关鉴权、多租户隔离等机制**保持运行**（它们同时承担功能路由与数据隔离作用），但**不继续深化、也不花时间拆除**。
3. **仅保留两条安全底线**：
   - 真实第三方凭证（百度地图 AK、微信/支付宝商户密钥、短信密钥等）**不写入仓库**，走环境变量/部署注入；
   - **上线前**（真实用户/公网暴露时）另立生产加固清单，届时统一收紧：强口令、密钥外置、支付回调白名单、HTTPS、Same-Token 入站加固等——本期不预先实现。
4. 本定调与既有文档其他条款冲突时，**在 dev 阶段以本条为准**；本条不构成生产期口径的永久豁免，上线评审时重新校核。
5. **决策边界（2026-10-11 用户拍板）：用户定方向，实现层不请示。**
   - **必须问用户的，只有"方向"**：业务口径/规则变更（状态机、计费、订单流程、角色权限模型）；新模块/新中间件/新依赖引入；表结构重设计与跨 3 文件以上的架构性改动；UI 整体风格与布局方案取舍；生产/公网/不可逆操作、删数据删文件；全局 CLAUDE.md 红线清单内配置文件（compose/Dockerfile/nginx/注册表等）的改动。
   - **以下情形直接做、不问**：
     1. **符合《阿里巴巴 Java 开发手册》的常规实现**——命名见名知意、分层、参数校验、空值/集合边界、异常处理、日志写法、魔法数字消除等，按手册执行即视为已授权；
     2. **符合市场通行规范/行业惯例的选择**——RESTful 语义与 HTTP 方法/状态码、标准日期时间格式、分页参数惯例、BCrypt 口令哈希、常规索引与字段类型、标准前端组件用法等，按通行方案直接落地，不提供选项让用户选；
     3. **符合国家/行业强制规范的合规细节**——规范有明确规定的按规定实现（如实名字段、留存、日志审计等），不就"要不要合规"请示；
     4. 简单 bug 修复、编译错误、单文件内重构、判空/边界/NPE、文档已明确规定的内容——直接按文档做，**禁止就同一条款反复确认**。
   - 台账《03》《54》等文档中的历史"拍板/待确认"记录是**决策留痕**，不是待办请示；只在要**改变**其结论时才重新提，照做时不提请。
   - 判断不了属于"方向"还是"实现"时，默认按实现直接做，并在交付说明里一句话写明自行决策的点。

### 3.5 鉴权链路与已知坑（2026-10-06 实测，开发必知）

**请求链路**（xfwl-gateway Sa-Token 体系）：
```
前端(token 头) → 网关8760（xfwl-gateway）
  ├─ SaTokenConfigure(SaReactorFilter)  白名单 /api/auth/anno/** 放行；其余 StpUtil.checkLogin()（未登录 → 401）
  └─ ForwardSameTokenFilter(GlobalFilter)  注入 Same-Token（防绕网关直连）+ tenantId/userid 透传
  → 下游服务 TokenAuthInterceptor（xfwl-common）检查 userid 头（缺 → 401）
```

**已踩过的坑**（改代码前务必确认）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 网关报 500 | 走网关接口异常 | 先看服务日志定位 `SaTokenConfigure`/`ForwardSameTokenFilter`/下游异常；Sa-Token 类 addExclude 必须放行 `/actuator/**`（compose 健康探针无凭证，否则部署探活必挂） |
| 菜单接口 userId 为 null | 登录成功但**左侧菜单为空** | 菜单按角色授权（`sys_menu`+`sys_role_menu`），菜单为空先查角色是否绑了 `sys_role_menu`，勿当缓存问题排查 |
| 菜单脏缓存 | 改完代码仍空菜单 | xfwl-auth 无进程内缓存（实测无 `@Cacheable`/Caffeine），**刷新页面即生效，无需重启** |
| 接口"未知请求" | 路由 404 | 未注册进 `xfwl-gateway` `routes`（`discovery.locator.enabled:false` 无自动路由），新增对外接口须显式加一条路由 |

> **登录态 ≠ 细粒度权限**：网关只校验登录态 + 端前缀角色，细粒度权限＝`sys_menu` 按钮型 `perm` + `@SaCheckPermission`（实测仅 `xfwl-auth`/`xfwl-web-manager` 在用）。验证权限真生效：换合法但无该权限的角色 Token 重调，仍 200 即说明权限点未落地。

> 📖 **接口不工作时的标准排查流程**见《28-环境故障排障手册.md》（含探活、直连对比、过滤器定位、缓存清理四步法）。

## 第 4 章 编码规范

1. **命名**：类 PascalCase、方法/变量 camelCase；接口名以 `XxxService`、实现 `XxxServiceImpl`；Mapper 沿用 `XxxMapper`；实体在 `entity`。
2. **分层**：controller（入参/出参/鉴权）→ service（业务）→ mapper（持久化）；不在 controller 写业务，不在 mapper 写业务。
3. **事务**：写操作加 `@Transactional`（沿用既有）；单库多租户后，跨域写通过「编排下沉到同一进程 + 本地事务」保证强一致（见 §6.13），不新造分布式事务方案，不再使用 Seata（2026-10-10 移除）。
4. **日志**：用项目既有日志门面（slf4j）；禁止 `System.out.println`；敏感信息（手机号/证件）脱敏。
5. **异常**：业务异常抛 `RuntimeException` 子类或既有业务异常；全局异常处理器沿用既有，不新建。
6. **配置外部化**：cron、阈值、地图 Key、坐标类型、上报间隔等一律进配置文件/配置中心；不硬编码。
7. **SQL/MyBatis**：复杂查询用 MyBatis Plus 或 XML；禁止在循环内逐条查库（N+1），批量用 `in` 或批量接口。
8. **前端**：页面放 `pages/<角色>/`；公共能力放 `common/`；API 调用放 `api/`；状态放 `store/`；禁止在页面里写裸 `uni.request`（必须过拦截器）。
9. **数据层软删除 / 归档约定（P1 落 · 参照 Open TMS/EvolveTMS · 2026-10-07 并入）**：
   - 核心业务表（`oms_order` / `work_transport_order` / `work_task_transport` / `work_pickup_dispatch_task`）**新增 `deleted` 状态位约定**（`tinyint(1)` 默认 0，删除=置 1，**物理删除仅限运维 SQL 且留审计**），所有查询默认 `deleted=0`。
   - **归档**：按 R6-3 审计保留期（审计≥6 月 / 业务≥3 年）归档，归档走现有备份/清理任务，不新引归档组件。
   - **禁止**：业务代码 `DELETE` 核心业务表（历史教训：软删缺失导致对账/审计断链）；导出"已删除"数据须审计留痕。

## 第 12 章 UI 设计规范（强制引用）

> 移动端页面样式与结构受《13-UI设计规范与页面模板.md》约束，与本章同等强制力。核心红线摘录：

1. **只用组件库，不写裸样式**：100% 使用 uview-plus 组件，禁止用 `<div>`+`<style>` 替代布局/按钮/卡片。
2. **Token 全集中**：颜色/间距/字号/圆角/阴影只允许引用 §6 的 CSS 变量或 `uni.scss` 主题变量，禁止页面内写死 hex/px。
3. **三端同视觉**：客户/快递员/司机共用同一套 Token 与组件，仅做角色化强调（司机端按钮更大、对比更强），禁止三端各一套。
4. **结构走模板**：列表/详情/表单/地图/任务大厅/POD 六类页面套用标准骨架（见 UI 规范 §4），禁止自由布局。
5. **三态必做**：加载中/空/错误统一用组件库，禁止缺失其一。
6. **统一反馈**：加载/空/错/提示/确认/刷新分页全部走 uview-plus 组件，禁止自造。
7. **禁止清单**（详见 UI 规范 §7）：禁裸 HTML 布局、禁硬编码色值、禁第二套 UI/图标库、禁 emoji 图标、禁缺三态、禁绕过 `u-navbar`、`uni.request` 必须过拦截器。
8. **主题一处改全端生效**：`uni.scss`（覆盖 uview-plus 主题）+ `common/styles/variables.scss`（业务 Token）为唯一真源。
