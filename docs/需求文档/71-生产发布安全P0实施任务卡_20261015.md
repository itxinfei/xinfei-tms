## T-SEC-01 网关核心过滤器四件套 ★P0

**目标**：xfwl-gateway 补齐生产四件套中的“限流 + 日志”，覆盖 69 号文档 A1 / A2 / E2 / A19。

**涉及文件**：
- `xfwl-gateway/src/main/java/com/xinfei/gateway/filter/`（新建 `RequestLogFilter.java`、`RateLimitFilter.java` 或直接用 `RequestRateLimiter` 过滤器工厂）
- `xfwl-gateway/src/main/resources/application.yml`（路由级 `filters` 配置）
- `xfwl-gateway/pom.xml`（如引入 `spring-cloud-starter-gateway` 已含限流；Redis 限流需确认 `spring-boot-starter-data-redis-reactive` 在网关侧可用——网关已用 sa-token-redis，应已具备）
- 下游 17 个服务的日志配置（traceId 透传至 MDC，`logback-spring.xml` pattern 加 `%X{traceId}`）

**实施步骤**：
1. **限流（A1）**：`KeyResolver` 双 Bean——`ipKeyResolver`（取 A3 剥离后写入的真实 IP）+ `userKeyResolver`（取 token 转出的 userId，匿名回落 IP）。路由级配置：
   - `/api/auth/anno/login`：replenishRate=5, burstCapacity=5（按 IP）
   - `/api/auth/anno/captcha`：10/10（按 IP）
   - 其余路由默认：300/分/user、2000/分/IP 兜底
   - 超限统一 429 JSON：`{"code":429,"msg":"请求过于频繁，请稍后重试","retryAfter":<秒>}`
2. **请求日志 + traceId（A2）**：全局过滤器（order 在 ForwardSameTokenFilter 之后）记录 method/path/真实IP/status/耗时/traceId/userId；入站无 traceId 头则生成（`X-Trace-Id`），透传下游；下游 logback pattern 统一加 `%X{traceId}`。
3. **日志脱敏（E2）**：日志过滤器对 password/captcha/code/token/手机号(1[3-9]\d{9})/身份证 做正则替换为 `***`；同一套脱敏工具放 `xfwl-common` 供各服务日志复用。
4. **URL 过滤（A19）**：同一过滤器内前置校验——URL 长度 >2048 返回 414；路径含 `..`、`%2e`、控制字符返回 400。

**验收**：
- 压测 `/api/auth/anno/login` 第 6 次/分返回 429 且带 retryAfter；
- 多网关实例（T-SEC-06 集群）下限流计数共享（同 Redis）；
- 任意请求日志含 traceId，且可用该 id 在下游服务日志中检索到同一条链；
- 日志文件 grep 无明文密码/完整手机号；
- `curl "http://gw/api/../../etc/passwd"` 返回 400；超长 URL 返回 414。

**依赖**：T-SEC-02 的 A3（真实 IP 写入）须先完成或同批完成，否则限流按伪造 XFF 计数。

## T-SEC-02 网关安全配置加固 ★P0

**目标**：覆盖 A3 / A4 / A6 / A13，一次改完网关全部配置类加固。

**涉及文件**：
- `xfwl-gateway/src/main/java/com/xinfei/gateway/config/CorsConfigure.java`

- `xfwl-gateway/src/main/resources/application.yml`
- 4 个 BFF 的 `src/main/resources/application*.yml`（swagger 开关）：`xfwl-web-manager`、`xfwl-web-driver`、`xfwl-web-courier`、`xfwl-web-customer`（均在 `xfwl-web/` 子目录下）

**实施步骤**：
1. **头剥离 + 规格（A3）**：入站过滤器删除全部 `X-Forwarded-*`，写入真实 IP/协议；body ≤1MB（413）、header ≤8KB（400）。
2. **CORS 收敛（A4）**：`allowedOriginPattern` 白名单化（管理端域名 + 三端 H5 域名，Nacos/环境变量注入）；dev profile 保留通配。**逐端核对**：管理端 `xfwl-admin-ui-vue3`、司机/快递员/客户 H5 各一个 origin。
3. **端点收敛（A6）**：各 BFF swagger 加 `springdoc.enabled: ${SWAGGER_ENABLED:false}`，prod 显式 false；actuator 全局 `exposure.include: health`（除网关 health 探针外全部关闭）。
4. **安全响应头（A13）**：`SecurityHeadersFilter` 全局注入 HSTS / X-Frame-Options: DENY / nosniff / Referrer-Policy；CSP 分端配置：
   - 管理端 + API：`default-src 'self'` + 放行 `*.baidu.com`、`*.bcebos.com`（下单页地图）、wss 域名（大屏 WS）；
   - 司机/快递员端：`Permissions-Policy: geolocation=(self)`（定位上报是核心功能）；
   - 白名单配置化，新增域名须登记。

**验收**：
- `curl -I https://<域名>/api/...` 含全部安全头；
- 非白名单 origin 预检失败；白名单站点功能正常；
- 外网扫不到 /swagger-ui.html、/actuator/env；
- **三条 CSP 回归用例全过**：管理端下单页地图加载 / 大屏 WS 连接 / 司机端定位授权；
- 伪造 X-Forwarded-For 不影响 T-SEC-01 限流计数归属。

**依赖**：无（与 T-SEC-01 同批，A3 是其前置）。

## T-SEC-04 七服务入站鉴权（Same-Token） ★P0（最高优先）

**目标**：覆盖 B1 + V1 漏洞根除。七服务复用 xfwl-auth 强校验模式，加入站拦截。

**涉及文件**（七个服务）：

- 参考实现：`xfwl-auth/src/main/java/com/xinfei/auth/config/SaTokenConfigure.java`（:21 强校验 Same-Token）
- 各服务 pom 确认 sa-token 依赖在位（xfwl-common 应已传递）

**实施步骤**：
1. 逐服务复制 xfwl-auth 的 Same-Token 入站校验（校验网关注入的 Same-Token 头与本地配置一致，不一致 401）；
2. **放行清单最小化**：仅 `/actuator/health`（compose 探针）与各服务确需的外部直达端点（如 xfwl-oms `/pay/callback/{channel}` 支付回调——验签已有，见 T-SEC-09）；
3. 每服务本地 `mvn -o compile` + 容器内 curl 直连验证 401；
4. 全部完成后**才**允许进入 T-SEC-05 撤端口；
5. **xfwl-netty 长连接握手 token 校验（《69》A18 最小集，v1.6 提前 P0）**：netty 端口因设备/GPS 上报须对公网 published（T-SEC-05 保留），须在 `NettyServerHandler`/握手链路校验凭证（App/大屏 WS 握手带 token 校验登录态；设备侧 TCP 校验设备标识，与《10》R2-3 轨迹防伪造硬闸对齐）；连接数/消息频率限制属 P1 余项，本卡不做。

**验收**：`curl http://<宿主IP>:<服务端口>/...` 无 Same-Token 一律 401；无凭证 WS/TCP 握手被拒（A18 最小集）；经网关全业务回归通过（下单→调度→运输→结算主链路 + 大屏 + 三端各抽 1 条）。

**依赖**：无（最先做）。**注意**：本卡与 T-SEC-05 是“先鉴权后撤端口”的两半，严禁颠倒或只做一半。
