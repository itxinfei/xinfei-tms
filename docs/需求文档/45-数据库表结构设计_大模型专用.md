## 一、架构总览：逻辑分域、物理单库、未来可拆

| 项 | 口径 |
|---|---|
| 物理库 | **仅 `xinfei_tms` 一个**（字符集 utf8mb4 / utf8mb4_0900_ai_ci） |
| 隔离方式 | 业务表带 `tenant_id`，由 MyBatis-Plus `TenantLineInnerInterceptor` 自动拼接条件；公共字典物理唯一、全租户共享 |
| 逻辑分域 | 表名前缀 `sys_ / dict_ / base_ / oms_ / disp_ / work_ / member_ / iot_`，前缀即**未来垂直拆库的物理库边界** |
| 演进策略 | 当前物理单库（本地事务够用、开发简单）；未来某域需独立扩容/部署时，可把该前缀表整体低成本迁出为独立库 |

**保证"未来可拆"的 6 条硬约束**：① 表按聚合唯一归属；② 禁止跨域物理外键（全库无外键，只存对方 id）；③ 雪花 BIGINT 全局唯一 ID；④ tenant_id 贯穿业务表（未来还可按租户水平分片）；⑤ 共享数据 dict_area 独立；⑥ 跨域通信走接口/事件。
**跨域读写纪律（用户拍板）**：**写操作严格只能本域服务写；读可适度跨域 JOIN，但优先走聚合/接口**。
**水平拆分预案**：仅高写入轨迹表 `iot_truck_location` 预留按月 RANGE 分区 + 冷热归档，其余业务表短期无需水平分表。

## 二、全局字段规范（所有业务表统一）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT UNSIGNED | 主键，应用层雪花 `@TableId(ASSIGN_ID)`；dict_area.id 例外（国标 int） |
| `tenant_id` | BIGINT UNSIGNED | 租户ID；平台表/字典表不带 |
| `create_by` | BIGINT UNSIGNED | 创建人 |
| `create_time` | DATETIME | 创建时间 |
| `update_by` | BIGINT UNSIGNED | 更新人 |
| `update_time` | DATETIME | 更新时间 |
| `deleted` | TINYINT UNSIGNED DEFAULT 0 | 逻辑删除 `@TableLogic`（0 未删 1 已删） |

类型规约：状态/枚举 `TINYINT UNSIGNED`（Java 枚举映射，**禁硬编码数字**）；布尔 `TINYINT UNSIGNED`；金额 `DECIMAL(12,2)`（禁 float/double）；经度 `DECIMAL(10,6)`、纬度 `DECIMAL(9,6)`。表间一律**不建物理外键**。
