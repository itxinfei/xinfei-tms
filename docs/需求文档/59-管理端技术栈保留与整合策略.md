> 配套约束：菜单/路由见《58-管理端菜单与路由开发规范.md》；多会话在途状态见《99-任务认领台账.md》。

## 0. 定稿决策（2026-10-12，用户原话口径）

> "这些技术栈我都可能会用，需求还没有完全确定，别人的物流项目用到的技术我这个项目可能都要用。"

**结论：管理端全部预置技术栈、演示页面、框架默认设置一律保留，不得删除。** 需求确定前，任何"减包 / 清理 / 顺手删除未引用代码"的动因都不成立。

## 2. 禁止事项（违反即失败）

1. **禁止删除 / 移出 §1 中的任何依赖、页面、组件、插件**（包括"未引用"的——本策略下未引用 = 预置备用，不是废弃）。
2. 禁止以**产物体积、chunk 过大**为由删依赖或页面（现状主 chunk 1.8MB、vxe 1.19MB 等均属可接受；如需优化只允许调 `build.chunkSizeWarningLimit` 或按需路由拆分，不动依赖）。
3. 禁止用其他 UI 库（Naive / AntDV / TDesign 等）**替换 Element Plus 作主 UI**——新库仅可作能力组件（外层仍是 Element Plus，视觉规范见《14》）。
4. 与其他会话冲突时以《99-任务认领台账.md》在途状态为准，**不得覆盖**正在进行的改动。

---

## 3. 整合新技术栈的标准动作（三步）

1. `pnpm add <dep>`（项目 `only-allow pnpm`，勿用 npm/yarn）。
2. 新建 `src/plugins/<name>.ts` 注册，`main.ts` 挂 `setup<Name>(app)`（照抄 `plugins/form-create.ts` / `plugins/vxe-table.ts` 范例）。
3. 封装 `src/components/<Name>/index.vue` 复用组件（参考 `components/ECharts`、`components/Upload` 封装模式），页面按《38》接入。

完成后必跑 `pnpm build`——`vue-tsc` 会拦截类型不兼容的库，报错即提示，不要绕过。

---

## 4. 注意点

- **主 UI 保持 Element Plus**；vxe / WangEditor / bpmn-js 等只做能力组件嵌入，视觉不冲突。
- 框架依赖较新（Vite 8 / Rolldown / TS 6 / Router 5 / Pinia 4），个别冷门 vite 插件或老库可能需等生态适配；`vue-tsc` 报错即提示，勿降级框架版本迁就。
- **架构红线不可动**：`router/views.ts` glob、`utils/request.ts`、`settings.ts`、`layouts/composables/useLayout.ts` 的 `flattenSidebarRoutes`——整合新栈不需要动它们（详见《58》）。
- 新增页面自动进组件树（`views.ts` glob），菜单管理页可选组件；业务页接入按《38》《43》。
