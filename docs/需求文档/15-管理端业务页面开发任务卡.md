## 〇、开发前置约定（所有页面通用）

1. **请求封装**：统一走 `src/utils/request`（Axios），`baseURL = /api`，自动注入 `token` 头；`code!==0` 视为失败；401 清 token 跳登录（无刷新）。禁止裸 `fetch` 直连（ofpay/customer 旧实现需整改）。
2. **设计 Token（取值真源＝《13-UI设计规范与页面模板》§2.1）**：管理端新增 `src/styles/tokens.scss` + `element-variables.scss`，**品牌主色统一心飞红**（D-10 定案；主色/按压/浅底及全套 Token 取值见《13》§2.1；**废弃** Element 默认蓝系及旧主色 `#2B6CFF`/`#E15536`——废止清单见《13》§2.1；落地即 `tokens.scss` + `element-variables.scss` 两处各改，禁止逐页硬编码），所有色值/间距/字号走变量，**禁止页面内硬编码 hex**；页面模板/图表/地图/禁止清单/DoD 均以《14》为准。
3. **分页参数**：统一用 `page` + `pageSize`（驼峰，现行契约）；旧"`pagesize` 小写"口径已废止。
4. **地图能力（技术选型已锁定，依赖尚未落地）**：在途监控/调度一张图采用**百度地图 JS API GL**，显示层做 WGS84→BD-09 转换（后端统一存 WGS84，见 BA-19）。**现状**：`package.json` 的 dependencies **未引入** `vue-baidu-map-3x`，`public/index.html` 也**未引** GL JS 脚本（仅有百度统计 `hm.js`），src 下**暂无**地图 ak 配置项——落地本页时须二选一新增依赖或在 `index.html` 注入 GL JS 脚本，并配置真实百度 ak（开发期可用测试 key 或 mock 数据先行）。移动端小程序侧用腾讯地图（GCJ-02）不受影响。
5. **复用现有组件**：列表用 `el-table` + `el-pagination`；表单用 `el-form` + `el-dialog`；下拉用 `el-select`（数据源走 `CommonController` 的 `common/*/simple`）。
6. **菜单登记（后端动态下发方案，`D-42`）**：每建一个业务页，除创建 `@/views/${path}.vue` 外，**必须在后端 `sys_menu` 登记菜单型（`type=M`）记录**（含 `name`/`path`/`component`/`icon`/`sort`/`visible`），并用 `sys_role_menu` 给对应角色授权，否则侧边栏不显示入口；登录后经 `GET /api/v1/menus/routes` 下发按角色 RBAC 过滤后的路由树。需要细粒度权限的接口另登记按钮型（`type=B`）记录的 `perm`，接口上加 `@SaCheckPermission`（真源《12》§7 第 4 条、《62》）。

## 六、统一告警中心（**P0 七页之一 · OPS-0**）

**现状**：告警后端在 **xfwl-netty**，表是 **`iot_alarm_record`**（脚本 `sql/iot/告警记录_建表.sql`）。🔴 **`xfwl-web-manager` 没有任何 alarm 接口**（勿新建 AlarmController / `/web-manager/alarm/*` 路径 / `pd_transport_alert` 表），前端**禁止**写 `/api/manager/alarm` 前缀，一律走网关 `/api/netty-service/alarm`。

| 页面 | 路由 path | 功能 | 对接接口（xfwl-netty） | 验收标准 |
|---|---|---|---|---|
| 告警中心 | `alarm/index` | 列表 + 筛选（alarmType/status）+ 标记已处理 + 未处理红点 | 见下表三接口 | 列表渲染、筛选、处理；红点取未处理总数 |

**真实接口（走网关 `/api/netty-service`，须按现行落点登记权限）**：

| 方法 | 网关路径 | 说明 |
|---|---|---|
| GET | `/api/netty-service/alarm?page&pageSize&alarmType&status&transportTaskId` | 分页，`Result.data={items,total,pages,page,pageSize}`（⚠️参数 **pageSize** 驼峰、计数叫 **total** 非 counts） |
| PUT | `/api/netty-service/alarm/{id}/handle` | 处理告警，**无 body、幂等**，status 0未处理→1已处理，重复调用不报错 |
| POST | `/api/netty-service/alarm/report` | 人工上报告警（管理端一般不直报；主要供三端经各自 web 服务转入） |

- **告警来源**：自动告警仅 3 类 `SPEED_OVER` 超速 / `STAY_TOO_LONG` 长时间停留 / `DEVIATE_ROUTE` 偏离路线（GpsAlertService 产生）；人工记录来自司机 D-57、快递员 D-41。
- **状态只有 0 / 1 两态**：页面只渲染"标记已处理"，**不要**做认领/转派/忽略/关闭按钮，也不要展示 assignee/handler/handleRemark 等不存在的字段。
- **未处理红点**：无独立 count 接口，用 `GET /alarm?page=1&pageSize=1&status=0` 取 `total`。

**开发策略**：接口已就绪，页面直接对接、**不再使用 mock**；确需占位时按上表真实结构造 mock，就绪后只换实现。
**排期**：页面为 **P0 七页之一（W3–W4）**，不阻塞 M1 合规硬闸（硬闸仅 FR-30/31/36；R6-3 审计日志页为另列 P0 合规项）。

**通知触达闭环（A-4/A-5 · P1 扩展，对标 G7 告警推送）**：
告警中心只"看得到"不够，须**推得出去**。规划新建横切组件 `NotifyController`（`xfwl-web-manager`）——⚠️ **当前不存在、属 P1 待建**，下文接口均为规划口径，前端本期勿对接：
